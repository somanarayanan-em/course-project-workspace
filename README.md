# Course Project Workspace

This is the **project workspace repo** used in the **AIDE Deep Dive course** (also known as the AIDE Crash Course). It is the starting point for the hands-on exercise, and it holds the framework and the project configuration that everything else in the session hangs off.

It is one of three course repos, cloned side by side:

| Repo | Holds |
|---|---|
| **`course-project-workspace`** (this one) | `project.toml`, `features.toml`, the A.I.D.E. install, your `.code-workspace` |
| [`quic-notes-knowledge-base`](https://github.com/somanarayanan-em/quic-notes-knowledge-base) | `ARCHITECTURE.md`, `components/`, and the `source-docs/` deposits reverse engineering produces |
| [`quic-notes-specifications-repo`](https://github.com/somanarayanan-em/quic-notes-specifications-repo) | The requirements, design, implementation, and quality packages |

The application you will be working on, **ElectricWealthAIDE**, is cloned as a fourth sibling. Nothing is nested inside anything else.

## Nothing is ever merged into `main`

`main` is protected, and not because something is waiting to be reviewed. **Nothing from the course is ever merged into it.** It is the clean starting point every participant clones, and it has to stay exactly as you found it so the next person — and the next run of the course — starts from the same place.

So there is no pull request to raise, no approval to wait for, and nobody reviewing your work. You cannot push to `main`, you are not meant to, and none of that is a problem to solve. **Your branch is where your work lives and stays.**

## Start on your own branch

Everything you do during the session happens on a branch of your own.

```bash
git clone git@github.com:somanarayanan-em/course-project-workspace.git
cd course-project-workspace
git checkout -b <your-unique-branch-name>
```

Pick a branch name that is unique to you, for example `jdoe/aide-deep-dive` or `aide-2026-09-jdoe`, and **use the same name in all three course repos**. Nothing enforces that; it just means you never have to work out which branch you are on in which folder. If your instructor has already cut branches for you, `git branch -r` will show them and you check those out instead.

Push early and push often. The branch is yours, so there is nothing to coordinate and nothing to break.

## What lands in here

This clone is the **workspace folder** — what A.I.D.E. calls `{project-root}`. As you work through the exercise it fills up with:

- `AIDE/` — the framework, installed by your agent from the source URL and release tag you are given on the day
- `.agents/skills/` and `AGENTS.md` — generated by the install
- `project.toml` — including the paths pointing at the two sibling repos
- `features.toml` — the feature registry, written by `/start-project`
- your multi-root `.code-workspace` file, if you are on VS Code or Cursor

All of that is meant to be committed. It is the state that lets you close your laptop mid-flow and pick the work up later.

**The specifications and the knowledge base do not land here.** They go to their own repos, which is the point of there being three. `project.toml` is what wires them together:

```toml
[project.paths]
requirements_package   = "{project-root}/../quic-notes-specifications-repo/requirements"
design_package         = "{project-root}/../quic-notes-specifications-repo/design"
implementation_package = "{project-root}/../quic-notes-specifications-repo/implementation"
quality_package        = "{project-root}/../quic-notes-specifications-repo/quality"

knowledge_base_path    = "{project-root}/../quic-notes-knowledge-base"
```

## This repo should otherwise be empty

Aside from this README and `.gitignore`, `main` contains **no other files**. That is the expected starting state for every participant.

If you clone it and find someone else's work already on `main`, say so rather than building on top of it — it most likely means a previous run of the course was merged in by mistake.

## What is deliberately ignored

`.gitignore` excludes the things that are personal to your machine rather than part of your work: `project.user.toml` (your role and your active feature), IDE directories, OS noise, and the knowledge-base drift and coverage reports.

It also excludes `quic-notes-knowledge-base/`, `quic-notes-specifications-repo/`, and `ElectricWealthAIDE/`. Those lines only matter if you are on IntelliJ and following the nested layout in the setup guide's appendix, where the other three repos are cloned *inside* this one. On the standard multi-root layout they are siblings and the lines do nothing — but leave them in either way, because without them Git records nested checkouts as gitlinks and `git status` becomes unusable.
